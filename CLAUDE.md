# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Chrome MV3 extension (plain JS, no dependencies, Chrome 134+: `minimum_chrome_version`) that badges Vinted listings with the seller's country and dims/hides listings from sellers outside the user's chosen country. It started from one user's need (they're in Ireland: shipping from an Irish seller costs about €3, from France about €8), but it's meant to work for any Vinted country.

## Development

There is no build step, package manager, linter or test suite for development: the files load as they are. (`scripts/build.sh` only packages releases; see below.)

- Syntax check: `for f in *.js; do node --check "$f"; done`
- Run: `chrome://extensions` → Developer mode → **Load unpacked** → this folder. After an edit, click reload on the extension card and then reload the Vinted tab. Tabs left open from before the reload keep the old script. It notices it has been cut off (`alive()` in `content.js`) and stops, so they need a reload to pick up the new version.
- Quick test without installing: paste `inject.js` and then `content.js` into DevTools on a Vinted search page. That doesn't reproduce `document_start` timing, the isolated world, or `chrome.storage`, so an installed load is the real test.
- UI and page behaviour can be tested in headless Chrome: serve a fake grid page over local HTTP (not `file://`, where `location.origin` is `"null"` and `postMessage` throws), stub `chrome.*` (including `chrome.runtime.getURL`, which should point at the real `tokens.css`/`ui.css`) and `fetch`, and load the real `shared.js`, `content.js` and `content.css`. The panel and lightbox are in a shadow root: reach them with `document.getElementById("vlf-root").shadowRoot`. Headless Chrome only runs animation frames when it takes a screenshot, so mid-test measurements see stale state. Replace `requestAnimationFrame` with a ~16ms `setTimeout` in the test page.

`icons/` PNGs were generated by a throwaway pure-Python script (no image libraries are installed). They're a teal rounded square with a white map pin, if they need redrawing.

## Releasing

- `scripts/build.sh` builds `dist/vinted-country-filter-<version>.zip` from committed files at HEAD. It leaves out repo-only files (`.github/`, `docs/`, `store/`, `scripts/`, docs) and fails if the manifest references a file that isn't committed. This zip is what gets uploaded to the Chrome Web Store.
- To release, run `scripts/release.sh <version>`. Add `--dry-run` to run only the checks, or `--yes` to skip the prompt (needed when not in a terminal). Before changing anything, it checks: the version looks like x.y.z; you're on `main`, with nothing uncommitted and in sync with `origin/main`; tag `v<version>` doesn't exist locally or on GitHub; the version is newer than every existing tag and not below `manifest.json`. It then sets the manifest version (committing "Release <version>" if it changed), and pushes `main` and an annotated tag. The tag push makes `.github/workflows/release.yml` build the zip on GitHub and create the release, with the zip attached and auto-generated notes. The workflow also fails if the tag and manifest version differ. `v0.*` tags become pre-releases.
- Web Store listing text and privacy-tab answers are in `store/listing.md`. The privacy policy is `PRIVACY.md`.

## Architecture

There are two content scripts, and they run in different JS worlds (see `manifest.json`):

- **`inject.js`**: `world: "MAIN"`, `document_start`. It runs in the page's own JS context so it can hook `window.fetch` and `XMLHttpRequest`. Its only job is to build an item ID → seller user ID map. It reads responses and never modifies them.
- **`content.js`**: isolated world, `document_idle`. It has access to `chrome.storage`. It looks up seller countries, draws the badges and the settings panel, and applies the filter.
- **`content.css`**: only what goes inside Vinted's own DOM (badges, the photo button, dim/hide), injected by the manifest. **`ui.css`** styles the panel and lightbox, and **`tokens.css`** holds the colour tokens shared with the popup (`light-dark()` with `color-scheme: light dark`, so they follow the OS). Both are `web_accessible_resources` because `content.js` fetches them and adopts them into its shadow root (`loadSheets()`, part of `ready`).
- **`shared.js`**: loaded just before `content.js` in the same content-script entry (so its top-level `VLF_*` / `vlf*` names are globals there), and by `options.html`. It holds the domain → country map, which is also the country picker's list, and the settings defaults.
- **`options.html` / `options.js`**: the settings UI, used both as the toolbar popup (`action.default_popup`) and as the options page. Keep it popup-sized (300px wide). It edits the same settings as the in-page panel. Both sides listen to `chrome.storage.onChanged`, so a change in one shows up in the other and in every open tab.

The popup gets the in-page counts for its "this page" card by sending `{type: "vlf:stats"}` with `chrome.tabs.sendMessage` to the active tab, about once a second while open. `content.js` replies with `{shown, total, pending}` from its last `apply()`, plus `paused` (seconds left of a 429 pause, or 0). No reply (not a Vinted tab) means the empty state.

`inject.js` and `content.js` communicate only through `window.postMessage` on `location.origin`:
- `vlf:owners` `{pairs: [[itemId, userId, photoUrl], ...]}`: inject → content. `photoUrl` is the main photo's `f800` URL, or `""` if the payload had none.
- `vlf:rescan`: content → inject, sent after content.js loads. inject.js replies with every pair it already knows, because its first posts happen before content.js exists.

### Where seller IDs come from (checked on live vinted.ie, 2026-09-24)

Search results never include the seller's location, only their user ID.
- **Page 1** is server-rendered. The data is in inline Next.js flight scripts as escaped JSON: `"productItem":{"id":X ... "ownerId":Y`. See `scanFlightText`. Client-side navigations deliver the same format as `text/x-component` fetch responses.
- **Pages 2+** load by XHR from `api.vinted.ie/svc-catalogue/items`. Each item has `item.user.id`, which the generic `collect` walker finds. `photoOf()` takes the main photo from `photo`/`photos[0]` (the `/f800/` thumbnail, then `full_size_url`, then `url`; f800 first so the lightbox's first photo matches the item page's list). The page-2 photo shape hasn't been checked live.
- **Home page** (checked live 2026-09-25): the first 20 feed cards are inline as `"type":"item","entity":{"id":X,..."user":{"id":Y` (see `scanEntities`; their only photo is a 310x430 thumbnail, so no photo URL). "Load more" fetches `api.vinted.ie/homepage/homepage`, whose items have `user_id` (a string) instead of `user.id`.
- **Promoted closets** (the seller promotion box, home and search): `/api/v2/promoted_closets`, items with `user_id`. The box itself is `data-testid="closet-promotion-<sellerId>"`, so `cards()` also takes the seller from there.
- **Listing page rails** ("Member's items", "Similar items"): `api.vinted.ie/item-details/more-items/<id>`, items with `user_id`. **Profile pages** use `/api/v2/wardrobe/<id>/items`, items with `user.id`.
- `collect()` accepts `user_id` only on objects that also have a photo or an `/items/` URL, so other objects carrying a `user_id` aren't taken for listings. New endpoints must match `interesting()` in `inject.js`.
- Search data also has title, price, total price with fee, brand/size/condition (`itemBox`), favourite count and promoted flag, but **only the first photo** (`photos[0]`, signed `f800` URL, the largest size served). Image URLs are signed per size, so a thumbnail URL can't be rewritten into the `f800` one.

### Photos and the lightbox

- A listing's other photos are only on its own page (`/items/<id>-<slug>`, ~2 MB). `loadPhotos()` fetches it when the lightbox opens, never for the whole grid, and caches the result in memory for the page view. It doesn't go through `pump()`: these are page loads on demand, not `/api/v2/users` lookups.
- `parsePhotos()` unescapes the flight data, cuts out the first `"photos":[…]` array with `sliceJson()`, and takes each photo's `/f800/` URL, main photo first. The item page also contains the seller's profile picture as an `f800` URL, so the fallback scan of all `f800` URLs can include it. Prefer fixing the array parse over widening the fallback.
- The `.vlf-zoom` button is added next to each badge. Clicks are caught in the capture phase on `window` (`preventDefault` + `stopPropagation`), so Vinted's full-card link doesn't navigate. The button's z-index must stay above that link.
- The lightbox is a `<dialog closedby="any">` in the shadow root, opened with `showModal()`: top layer, the rest of the page inert, focus kept inside, and Esc or a click on the backdrop closes it, all native. The dialog box is only the photo and its bar; the round buttons are `position: fixed` to the viewport edges, so clicks around the photo land on the backdrop. Its `close` event runs `closeLightbox()` whichever way it closed. It opens instantly with the `f800` main photo from `inject.js` (or the card's `<img>`), then swaps in the full list. ←/→ are handled on the dialog. It locks page scroll while open. The filter switching off, or `alive()` failing, closes it.

### Country lookup

- `GET /api/v2/users/{id}` (relative to the page origin) works without logging in. It returns `user.country_iso_code`, `country_title` and `city`.
- **Rate limit:** about 30 requests per 30s, after which it returns 429. Every lookup starts in `pump()`, which allows a start only while fewer than `limit` started in the last 30s and fewer than `burst` in the last 3s (sliding windows over `starts`). Up to `CONCURRENCY = 4` run at once. The result is an immediate burst for the listings on screen, then a steady rate. Lookup order: `want(id)` only adds sellers to the end of the queue. At the end of each `apply()` pass, `prioritize()` reorders the queue by card position: on screen, then within 400px below, then within 200px above, then the rest, each in reading order (row, then left to right). Hidden cards (empty rect) aren't ranked. Queued sellers whose listings are no longer on the page (new search, filter or page change) are dropped, so they don't use up the rate limit. They're queued again if their listings come back. This is skipped while the page has no listings, so an empty grid mid re-render keeps the queue. This used to unshift each visible card, which reversed the order and looked up the top-left listings last. Keep any new code that starts lookups going through `pump()`, or the limits stop holding.
- Start times are also kept in the tab's `sessionStorage` (`vlf:starts`), so a reload or the next search within 30s doesn't burst into a window Vinted is still counting.
- `limit` (start 25, 8–28) and `burst` (3–`limit`) are learned from 429s and saved in `chrome.storage.local` under `rate`. On a 429: many starts in the last 3s lowers `burst`, otherwise the 30s count lowers `limit`, and too few starts for either means the 429 came from elsewhere, so it only pauses. While a 429 pause is running and lookups are waiting, the panel shows an amber "Vinted is limiting lookups. Resuming in Ns" notice above its header (visible when collapsed too), and the popup's stats card shows the same (`pausedFor()`, also sent in the `vlf:stats` reply as `paused`). A 1s ticker redraws only the notice. The normal window/burst waits don't show it. Screen readers get one announcement when a pause starts (`announce()`), not the countdown. Only the first 429 of an event counts: others arriving while paused just requeue, so 4 in-flight 429s don't cause 4 pauses. The pause is 5s doubling to 120s, or `Retry-After`. Every 60 successes, `burst` then `limit` creep back up by 1.
- Pacing can be simulated in Node: extract the constants and the country-lookup section of `content.js`, run them on a virtual clock (stub `Date.now`, `setTimeout`, `sessionStorage`, `chrome.storage.local.set`) against a fake limiter that returns 429s, and compare time-to-first-screen, time-to-all and 429 count.
- Results are cached in `chrome.storage.local` under `users` (`{userId: {c, name, city, t}}`, 90-day TTL, newest 20,000 kept; `saveUsers()` merges with what's stored so tabs don't overwrite each other, and skips sellers with no country so they're retried). Settings are in `chrome.storage.sync` under `settings`: `{enabled, country, mode, hideUnknown, collapsed}`. `country` is a single ISO code, or `""`, which means "the country of the Vinted site being viewed" (`homeCountry()` in `content.js`). Always read stored settings through `vlfSettings()` in `shared.js`: it fills in defaults, converts 0.1.0's `allowed` list, and resets a country the picker doesn't offer.
- `content.js` waits for `ready` (cache and settings loaded) before rendering. `syncPanelInputs()` refreshes the panel inputs whenever settings change, including changes made from the popup.

### DOM

- A card is found from its overlay link: `a[data-testid$="--overlay-link"][href*="/items/"]` (`CARD_LINK`). The card is the ancestor whose testid is the link's minus `--overlay-link`, and the item ID comes from the href. This covers `product-item-id-N` (search, profile), `feed-item` (home), `item-N` (promoted closets) and `similar_items-N` / `other_user_items-N` (listing page). The badge goes inside `[class*="image-container"]`, which also holds the link, so the photo button finds its listing through its parent.
- The cell that gets dimmed or hidden is the whole promoted-closet box (one seller), else `closest('[data-testid="grid-item"]')`, else the card's wrapper when the card is its only child (listing-page rails), else the card.
- `apply()` runs from `requestAnimationFrame` (`schedule()`), triggered by a MutationObserver on `<html>`, scroll, and new data. It only writes to the DOM when a value has changed, and the observer ignores nodes the extension adds, so its writes don't retrigger it. Any removed element counts as a page change, even the extension's own.
- The panel and lightbox live in a shadow root on `<div id="vlf-root">` (`root()`), so Vinted's CSS can't reach them and theirs can't leak out. `:host { all: initial }` blocks inherited styles; `color-scheme` is set again after it. The MutationObserver doesn't see changes inside the shadow root, only the host being added or removed.
- Vinted's React hydration can re-render `<body>` after the host is added and drop it. `root()` re-appends it whenever it's disconnected. That's why removals must trigger a pass.
- Reloading or updating the extension cuts off the copy of `content.js` already running in open tabs, and every `chrome.*` call then throws "Extension context invalidated". `alive()` checks `chrome.runtime.id` before saves and before each queued pass. Once cut off, the script disconnects the observer and removes the shadow host. Guard any new `chrome.*` call the same way.
- The panel's DOM order is body, notice, header, in a plain column, so the header row (with the collapse chevron) sits at the bottom and Tab order matches the layout. Don't reorder with `column-reverse` or `order`. The body collapses by animating `block-size` between `0` and `auto` (`interpolate-size: allow-keywords` on `:host`), so it fits whatever settings it has. A collapsed body is `inert`, and the toggle has `aria-expanded`/`aria-controls`.
- Screen-reader announcements go through `announce()`: one polite `role="status"` region in the shadow root, used for "Saved" and for a 429 pause starting. The stats line and countdown aren't live regions, since they change constantly. `announce()` does nothing while the lightbox is open (the modal makes the panel inert).
- `enabled: false` makes `apply()` hand off to `applyOff()`, which closes the lightbox and removes badges, photo buttons and dim/hide classes, and makes `pump()` start no new lookups. The queue is kept, so lookups resume when the filter is turned back on.
- Badge `data-state`: `match`, `other`, `loading` (lookup queued; pulses) or `unknown`. "Filter unknown" applies to `unknown` only, never to `loading`.
- CSS classes that go into Vinted's DOM (`content.css`) and message types use the `vlf` prefix. Classes inside the shadow root (`ui.css`) don't need one.
- `apply()` reads first (owners, cache, card positions) and writes after (badges, classes), so a pass causes one layout, not one per card. Keep new DOM reads in the first pass.
- The popup and panel follow the design canvas at https://claude.ai/artifact/1acQYEuLV1zsYxG2XtpJCN. Dark mode follows the OS through `color-scheme: light dark` and the `light-dark()` tokens in `tokens.css`. The switch's off track (`--switch-off`) is kept at 3:1 contrast or more, and the custom switches and segmented control have `forced-colors` outlines.

Vinted's markup, its inline data format and its internal endpoints can change without notice. When something breaks, check those first.
